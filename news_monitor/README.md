# B站官方账号资讯监控器

这是原评论爬虫之外的一套独立工具。它读取指定 B站账号的近期公开动态，提取发布时间、正文、标题、类型和原始链接，保存为适合日报继续处理的 JSON。

原项目文件不需要修改，也不需要安装数据库、Docker 或额外 Python 包。

## 第一次使用

1. 安装 **Python 3.10 或更高版本**。安装 Windows 版时勾选 `Add Python to PATH`。
2. 打开本文件夹中的 `config.json`，填写要追踪的账号。
3. 双击 `run.bat`。
4. 查看 `output/latest.json`。

默认已经加入：

```json
{
  "name": "重返未来：1999",
  "uid": "1197454103"
}
```

增加账号时，在 `users` 列表里复制一个对象并修改名称与 UID。注意上一项末尾要有英文逗号：

```json
{
  "users": [
    { "name": "重返未来：1999", "uid": "1197454103" },
    { "name": "另一个官方账号", "uid": "123456" }
  ]
}
```

## Cookie：先不要填

程序会先尝试匿名读取公开动态。如果能正常生成数据，什么都不用做。

如果 B站返回 `-101`、`-352`、`-412`，再进行以下操作：

1. 把 `.env.example` 复制一份，改名为 `.env`。
2. 在浏览器登录 B站，从开发者工具的网络请求中复制完整 Cookie。
3. 填到 `.env` 的等号后：

```text
BILI_COOKIE=SESSDATA=……; bili_jct=……;
```

`.env` 已被 Git 忽略。**不要把真实 Cookie 写进 `config.json`、截图、提交或发给任何人。** Cookie 失效后重新获取即可。

## 输出文件

```text
output/
├─ latest.json       # 最近一次检查结果
├─ 2026-09-21.json   # 当日多次运行的合并快照
└─ state.json        # 已见动态 ID，用于判断首次发现
```

每条动态的核心字段：

```json
{
  "dynamic_id": "123456789",
  "published_at": "2026-09-21T18:32:00+08:00",
  "type": "DYNAMIC_TYPE_DRAW",
  "title": "公告标题",
  "text": "动态正文",
  "url": "https://www.bilibili.com/opus/123456789",
  "is_new": true
}
```

`is_new` 表示该动态 ID 是否为本工具首次发现，不等于它一定刚刚发布。第一次运行时，时间范围内的内容都会标成 `true`。

## 指定日报时间窗

双击运行默认读取过去 48 小时。也可以在命令提示符中执行：

```bat
run.bat --since 08:00
```

这会只保留北京时间当天 08:00 之后的动态。也支持完整 ISO 时间：

```bat
run.bat --since 2026-09-21T08:00:00+08:00
```

## 自动运行

Windows 任务计划程序中，把“程序或脚本”指向 `run_scheduled.bat`。这个版本不会暂停等待按键，日志保存在 `logs/latest.log`。

建议频率为每天 08:00、12:00、18:00、20:00。不要设置成每分钟运行；频繁请求更容易触发风控，也没有资讯价值。

## 常见错误

| 提示 | 含义与处理 |
|---|---|
| `-101` | Cookie 缺失或失效；按上面的 Cookie 步骤处理 |
| `-352` | B站风控；降低运行频率，稍后重试 |
| `-412` | 请求被拦截；停止反复重试，稍后更换网络或 Cookie |
| `请求 B站失败` | 网络、DNS、代理或 B站临时异常 |
| 某账号 `status: error` | 只代表本次没抓到，不代表该账号没有更新 |

工具最多按配置读取少量页面，并在翻页之间等待；某个账号失败时会保留明确的错误状态，不会把“抓取失败”写成“没有动态”。

## 命令行选项

```text
python monitor.py --help
python monitor.py --since 08:00
python monitor.py --dry-run
python monitor.py --config 其他配置.json --output 其他目录
```

`--dry-run` 会打印结果但不更新快照和去重状态，适合检查配置。
